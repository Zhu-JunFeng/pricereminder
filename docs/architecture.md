# 架构

## 前台与本地后台数据流

1. 终端从币安 `GET /fapi/v1/exchangeInfo` 获取可交易的 USDT 永续合约和价格精度。
2. 终端根据主合约、菜单栏合约和已启用规则，优先直连币安 combined WebSocket `<symbol>@trade` 实时流，最多订阅 50 个合约。
3. 直连失败或 3 秒内没有收到有效行情时，终端立即注册到 PriceReminder 服务端，同步订阅并切换到 `/v1/stream`；服务端转发的仍是币安官方 `<symbol>@trade`。
4. 终端按币安事件时间把每个合约合并为每秒最新成交价，并维护最近 1 小时的本地环形缓冲。
5. 终端本地计算规则、本地保存 30 天触发历史，并通过操作系统通知提醒。
6. 两条链路断开后每 5 秒重连；服务端链路稳定运行时每 5 分钟重新探测终端直连。

## 全市场异动数据流

1. 存在已启用的全市场规则时，终端独立直连币安全市场实时价格流。Apple 端按合约目录分片订阅 `@trade`，Android 和 Windows 使用 `!miniTicker@arr`；两者都以 Binance 最新成交价和事件时间为准。
2. 终端只接收合约目录中状态可交易、报价资产为 USDT、类型为永续的合约；全市场流不使用 PriceReminder 中继或其他行情源。
3. 每条规则和每个合约分别维护单调最小值队列与最大值队列。当前价相对窗口内最低价的涨幅、相对窗口内最高价的跌幅达到阈值时立即触发，不要求窗口先积满。
4. 上涨和下跌方向分别重置；一个方向触发不会清除另一个方向的窗口。多个规则或方向在同一合约、同一事件时间命中时合并通知。
5. 低成交合约的稀疏价格点只要仍在配置窗口内就保留；全市场连接中断、规则编辑或重新启用时清空相关状态，下一条新价格作为新基准。

## 断线与一致性

- 所有窗口使用币安事件时间，不使用终端接收时间。
- 服务端中继连接通过 `lastEventTime` 补发其内存中保留的一小时价格；回放价格只补缓冲，不触发历史提醒。
- 规则只有在目标窗口基准点距离理论时间不超过 30 秒时才判断，缺口过大时继续积累而不误触发。
- 重连过程中不补发断线期间的历史越线。
- 同一秒内同合约多规则命中合并成一个系统通知。
- 全市场规则在启动、重连和重新启用后不读取本地一小时价格缓冲，因此不会追溯触发历史异动。
- 没有通知权限不阻断实时价格和规则计算，只停止系统弹窗提醒，并在状态中明确显示。

## 平台边界

- iOS 17.2+：App 活跃时直连币安并本地判断；进入后台后连接暂停，由服务端接管同一规则并通过 APNs 提醒。前台每 10 秒续租，服务端只在 25 秒租约过期后判断，避免重复提醒。全市场扫描在前后台两侧分别从交接后的第一条新价格建立基准，不传递前台滚动极值。
- Android 10+：前台服务维持直连币安或服务端中继 WebSocket 和常驻通知。用户强制停止后监控停止。
- 华为支持可运行 Android APK 的 EMUI/HarmonyOS，不包含 HarmonyOS NEXT 原生应用。
- macOS 14+：菜单栏最多显示三个合约，休眠或退出期间暂停，恢复后不补发历史提醒。
- Windows 10/11：原生通知区域程序最多展示三个合约；管理窗口关闭后仍在托盘继续监控，用户选择“退出”后停止，不补发退出期间的历史提醒。

## iOS 后台服务

`server/` 持续连接币安公开行情，保存匿名设备订阅、iOS 规则快照、前台租约和待确认事件。存在已启用的 iOS 全市场规则时，服务端额外直连 Binance mini ticker 数组流，并为每台处于后台的设备独立扫描。iPhone 回到前台时先合并服务端规则状态与后台事件，再恢复本地计算；Android、华为、macOS 和 Windows 的全市场扫描始终由终端直连币安，指定合约行情才会在直连失败时使用服务端中继。
