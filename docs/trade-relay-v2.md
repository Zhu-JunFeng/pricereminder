# 成交行情复用与在线全市场扫描

## 行为

四端默认先尝试币安直连，失败后使用服务端。直连模式在本地按秒聚合成交并扫描；开启全市场后，普通合约从同一成交流筛选，不另建普通行情连接。服务端模式通过 `/v2/stream` 发送配置，由服务器扫描，只返回所需合约价格和触发结果。黄金仍使用独立的五秒缓存接口，不加入全市场扫描。

同一服务器成交连接动态订阅所有有效需求的并集，沿用 `trade`，不替换为 miniTicker。已有 v1 接口及 iOS 后台 miniTicker 路径保留。普通合约最多 50 个，全市场规则最多 50 条。在线配置、窗口和事件去重只在内存中保存，不修改数据库结构。

## 协议 2

认证沿用设备 Bearer token。完整配置示例：

```json
{"type":"configure","protocol":2,"version":1,"symbols":["ETHUSDT"],"marketRules":[{"id":"00000000-0000-0000-0000-000000000001","windowMinutes":1,"thresholdText":"1","isEnabled":true}]}
```

服务端返回 `configured` 确认，再发送 `batch`。所有消息包含 `protocol`、`version`、`session`、`serverTime`、`latestEventTime`。批次可包含 `prices` 和 `triggers`；无成交时至少每十秒发送一次空批次作为心跳。`latestEventTime` 是来源成交时间，不能用单个冷门合约没有成交推断传输断线。

每个触发批次具有唯一 `eventId`；批次内每项包含规则 ID、合约、方向、窗口、阈值、初始价、提醒价和行情时间。客户端按事件 ID 去重，并拒绝非当前配置版本的事件。通知和历史仍由客户端处理。重复相同配置不清空窗口，修改规则仅替换该规则的扫描器。删除、停用规则后客户端立即停止接受其提醒。

连接代次隔离旧任务；上游连接中断会关闭 v2 会话。重连后重新积累窗口，不补发断线期间提醒。普通价格先初始化提醒状态，再进行后续计算，防止切换来源首条报价产生虚假穿越。恢复直连时仅先探测空 WebSocket，不提前订阅全市场。

## 聚合口径

每一秒交付各合约最新的一笔有效成交，独立记录合约时间戳，忽略重复或倒序数据。价格未变化但来源时间推进仍是有效行情。全市场与普通价格使用相同聚合结果；涨跌窗口及触发后上下方向独立重置保持既有扫描算法。实际收到的成交和交付时钟相位不同可能影响边界样本，不承诺网络不同情况下触发毫秒完全一致。

## 兼容上线与回退

先部署支持 v2 的服务端，再安装新版客户端；v1 不变，因此旧客户端可继续运行。v2 不存在或认证/协议失败时，新客户端明确记录连接错误并按既有方向回退直连。

生产部署仅替换 `/opt/pricereminder/pricereminder`，保留原二进制与配置；回退时恢复备份二进制并重启 `pricereminder`。Mac 正式安装仍为 `/Applications/PriceReminder.app`，安装前保存旧包，保持 Bundle ID 和用户数据不变。新版服务器可搭配旧客户端；回滚服务器时建议同时恢复旧 Mac，避免持续尝试不受支持的 v2 接口。

## 验证边界

核心检查覆盖滚动极值、连续触发、上下方向独立重置；v2 模拟测试覆盖订阅并集、逐合约水位、重复/乱序、配置幂等、只重置修改规则、停止全市场、旧连接替换及上游断线。发布验证分别报告本地构建、CI、线上部署、Mac 安装和流量观察结果。直连仍需下载全市场成交，只减少重叠订阅；服务器模式才避免客户端下载整个市场。
